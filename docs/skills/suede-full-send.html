What Full Send changes.

Full Send is a control policy for effort. It keeps one mission record, selects one controller, opens the maximum useful set of lanes that will not collide, and requires every important completion claim to resolve to proof, an explicit gap, or a blocker.

01 · Freeze

One mission

Goal, scope, authority, constraints, proof targets, and stop conditions stay visible so parallel work does not mutate the assignment.

02 · Allocate

Useful lanes only

Parallelism earns its place through independent evidence or non-overlapping ownership. Duplicate lanes and padding do not count as effort.

03 · Prove

Finish cleanly

The controller reconciles findings, challenges consequential calls, verifies the outcome, and reports what is proved, unproved, or blocked.

Pick one controller.

Full Send does not become a second orchestrator. It chooses the narrowest controller that can govern the mission, then stays at the intent layer.

complex suede-agent-teams Use communicating lanes for high-risk, cross-surface, or multi-stage work that needs shared context, review, recovery, and a signed handoff.
high-volume suede-codex-fleet Use independent worker units when the job benefits from volume, self-contained briefs, and mandatory controller review.
atomic smallest specialist Use one focused skill when the scope is narrow. Full Send does not turn a one-file fix into an orchestration ceremony.

House line

Never end your allocation above zero.

Plain English.

This is dry intent copy: use the available time, tools, and useful lanes to pursue the authorized outcome instead of coasting. It is not a literal counter promise, a hidden host counter, a change to model limits, or permission to spend money or act outside the user's authority.

Proof closes the loop.

Activity is not completion. The final mission record ties each material claim to current evidence and names anything the run could not truthfully prove.

Terminal state

PROVED

The acceptance condition was checked against current repo state, terminal output, a live service, or another task-appropriate source of truth.

Terminal state

UNPROVED

The work may exist, but the required verification was unavailable or incomplete. The handoff says exactly which proof is missing.

Terminal state

BLOCKED

A real dependency, authority boundary, or external-state condition prevents completion. The blocker and smallest next action stay explicit.

Authority does not expand. Full Send cannot authorize external spend, publication, destructive actions, third-party contact, or access that the user did not grant. It also cannot override legal, security, financial, privacy, or platform safeguards.

Ask for the outcome.

The best prompt gives Full Send a real finish line, the surfaces in scope, and any hard authority boundary. It can infer the useful lanes from there.

Use $suede-full-send to finish this authorized release across code, docs, CI, and production verification. Preserve unrelated WIP and return proof.
Use $suede-full-send to audit this public launch end to end, split only non-colliding lanes, challenge the strongest claims, and fix what is in scope.
Use $suede-full-send to take this broad repo outcome to a verified handoff. No external spend or publication without my explicit approval.
