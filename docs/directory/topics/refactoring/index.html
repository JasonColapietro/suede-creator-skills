How to choose refactoring skills

Run refactoring skills on a branch with tests in place. The skills that find duplicates or complexity report first; the ones that rewrite should go in small steps you can review.

Book-based skills (refactoring patterns, working with legacy code, clean code) set principles; task skills (extract method, remove parameter) do one change well. Use the first to plan and the second to execute.

For legacy systems, ask for characterization tests before the first change, so the agent can show behavior stayed the same.
