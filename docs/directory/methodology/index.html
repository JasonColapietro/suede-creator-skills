How skills are listed and graded

Directory / Methodology

The directory lists public Agent Skills that pass a published, mechanical check. This page is the whole method: where skills come from, what is checked, what gets a page of its own, and how to change a listing.

Where the skills come from

The directory reads the repositories cited by at least two of these 8 curated lists: BehiSecc/awesome-claude-skills, ComposioHQ/awesome-claude-skills, VoltAgent/awesome-agent-skills, heilcheng/awesome-agent-skills, hesreallyhim/awesome-claude-code, karanb192/awesome-claude-skills, skillmatic-ai/awesome-agent-skills, travisvn/awesome-claude-skills. It adds the official collections those lists name and repositories accepted through listing requests. Every SKILL.md in those repositories is read from the default branch, except in hidden folders and dependency or build folders (node_modules, vendor, dist, build), and nothing in them is executed. This snapshot was taken on October 17, 2026.

The Suede Skill Check

Eight checks: six on the SKILL.md format, following the Agent Skills format, plus a declared license and a commit to the repository in the last year. The first check is required; the grade counts the other seven.

  • Grade A: 90–100. All seven graded checks currently produce 100/100 (2,019 listed skills).
  • Grade B: 80–89. Six of seven currently produce 86/100 (956 listed skills).
  • Grade C: 70–79; grade D: 0–69. Scores below 80 are not listed. Failed required frontmatter receives grade F and remains ineligible regardless of score.

The quality score is round(100 × passed / 7), with equal weight for each graded check. The possible scores are 0, 14, 29, 43, 57, 71, 86 and 100. Missing evidence fails its check; the denominator stays seven. A source fetch failure is unscored and stops a refresh from replacing the published snapshot.

The score measures the recorded SKILL.md structure, license declaration and maintenance evidence. It does not measure runtime performance. Frontmatter is a separate required gate; a declared license and all listing-policy rules still apply.

Security scan status is separate

External directory skills are marked not scanned. The HOL/Cisco CI scanners run on Suede’s own repository; their results do not certify the external repositories listed here. The shields’ “Suede Certified” label refers to the published structural quality check. A security result needs its own per-skill scan evidence.

Two README badges and a limited-time feature offer

Skills scoring 80–100 receive separate numeric and A/B shields, each linking to their actual Suede listing. Scores from 90–100 and grade A use gold; scores from 80–89 and grade B use cool metallic styling. The Suede S remains the main mark on both shields.

Display either the numeric or letter badge in your repository or skill README, linked to your Suede listing, then request verification. Displaying both also qualifies. Suede checks the rendered README at a recorded commit before a feature placement is activated. An unverified request, no valid linked badge or failed fetch cannot activate promotion. Verification is checked again after a dataset refresh. Existing editorial full pages keep their separate rules.

Limited-time feature offer: display either the numeric or letter badge in your repository or skill README (both also qualify), then request badge verification. Eligible skills scoring 80–100 can receive a featured placement after Suede verifies at least one valid badge linked to the skill’s listing. Suede has not announced an end date.

Scored below 80? We welcome authors who want help improving their skills. Send your repository and the checks you want help with, then request a new review after updating the skill.

Listing rules

  • Grade A or B on the Suede Skill Check.
  • A license declared in the SKILL.md frontmatter or the repository. Every listing states it; 97% of listed skills use an open-source or open-content license, and pages for the rest flag the terms next to the license.
  • A description written mainly in English, so the directory's pages read consistently.
  • Templates, examples, drafts, test fixtures and folders named archive, deprecated, internal or prompts, or starting with an underscore, are skipped.
  • One listing per skill. A copy is the same skill name with a mostly matching description, or a description repeated word for word under another name. When copies appear in several repositories, the copy in the repository cited by the most lists keeps the listing.
  • Skills are not listed when they:
    • automate posting, messaging or account activity on a social platform (skills that draft posts or replies for a person to approve are listed);
    • work around a site's blocks, CAPTCHAs or official API;
    • have scraping a third-party site as their main job;
    • collect people's personal data by scraping a social network or map listings (skills that use licensed B2B data providers within their terms are listed).
    A vendor's skills for its own service are listed under the second and third rules. A repository whose product is one of these behaviors is left out as a whole.
  • Skills are also left out when their name or description trips the site's content filters: adult content, malware terms, jailbreaks outside a defensive context, the short list of terms the site's own public-copy guard rejects, and listing text that fails the site's public-privacy check (an email address, a phone number or a home-directory path). The exact terms are in curate.py. Removals at an author's request, and skills whose text matches the pack's reserved-text guard, are recorded with their reason in exclusions.json.
  • Suede's own skills are catalogued separately on this site and pass the same rules; a test in the repository checks every one of them against the policy.

Which skills get a full page

Every listed skill appears in its category directory and on its repository's page. Grade A skills get a page of their own once the directory's editors have written their one-sentence summary, up to twelve per repository, chosen by how much ships with the skill: reference files, scripts, assets and a structured SKILL.md. A skill keeps its page while it stays listed, so its README badge and link keep working. Each page carries the summary, a pre-install list of the scripts, commands, environment variables and network use found in the skill's files, install steps (or, where the license restricts copying, the publisher's terms), and a README badge. 729 skills have a full page in this snapshot. A repository whose single listed skill has a page is listed through that page.

Categories

Categories group skills by their main task, so you can compare alternatives side by side. Each skill sits in one of 16 categories, assigned from its name and description.

Refreshes and changes

Each refresh re-reads the source repositories, so quoted descriptions, file facts and check results follow the published SKILL.md. To request a listing, a correction or a removal, use the listing request page; requests are reviewed by hand.

The Suede Skill Check reads published SKILL.md files and the files beside them. It executes nothing.
