Who this stack is for

This stack is for people who have to ship an interface that looks considered rather than assembled. A founder building a first product without a designer. A frontend engineer handed a Figma link and a deadline. A design lead who wants an agent to audit a flow before review. A marketer who needs a product page that does not look like a template.

It also fits teams that want an existing product UI fixed, not rebuilt. That is exactly where impeccable earns its place.

All six skills use the Agent Skills format, so the same folders work in Claude Code, Codex, Cursor and any agent that reads a SKILL.md. The focus is web first: auteur, superdesign and web-artifacts-builder build for the browser, while impeccable also covers native iOS and Android screens. If you only write backend code, skip the stack; auteur and impeccable both say they are not for backend-only work.

The Suede AI skill built for this job

I built suede-design for exactly this job: taking an interface from a diff or a rough flow to something I would sign. Hand it a UI diff and it reviews it. Hand it a flow and it runs a whole-flow review. Ask it to design and it sets the hierarchy, tokens, color, type, accessibility and the design system they belong to. It restyles dashboards, and it verifies the visual build before anything ships.

Start with it. suede-design makes the hierarchy and token decisions first, and the third-party stack below executes against them. The design.md from anydesign becomes an input it reviews, not a spec you trust blind. Variants from superdesign get judged against one set of tokens. auteur builds to a system already decided, and impeccable polishes screens whose structure has passed review. At the end, suede-design verifies the visual build, so the skill that set the rules checks the pixels.

It is Suede AI's skill, so it stays out of the ranking on this page. It keeps to its lane: no sales copy, funnel architecture or general code and security review.

The skills, one by one

auteur: building a whole site or product as one system

auteur designs and builds complete web experiences from scratch: product and marketing pages, cinematic scroll-directed sites where the page is directed like a film, and multi-screen products (app, dashboard, admin, settings, onboarding, docs site) built as one design system, with every component, state and route in one style. That last part is the reason to use it. Screen twelve looks like screen one because the system came first.

Its SKILL.md reads like a production manual: non-negotiables, a banned list, critical numbers, routing, a commit-sheet to fill in before any code, phases, and a section titled "Verification is part of the build". It gates every ship with an executable anti-slop linter and a screenshot verification loop. It bundles nine JavaScript scripts, generates its own assets through local CLIs (images, video frames, depth maps, 3D), and its files reach api.iconify.design, www.pinterest.com, www.awwwards.com and api.polyhaven.com.

Reach for it when you start fresh, not to polish a UI someone else built. It is MIT licensed, with about 200 installs recorded by skills.sh.

A prompt that fits its brief:

Design and build a five-screen onboarding flow for a budgeting app as one design system. Fill in the commit-sheet first, then build, then run the screenshot verification loop.

web-artifacts-builder: multi-component claude.ai artifacts

web-artifacts-builder comes from anthropics/skills, which the directory marks as an official publisher. It is a suite of tools for elaborate, multi-component claude.ai HTML artifacts built with React, Tailwind CSS and shadcn/ui. The description draws the line clearly: use it for artifacts that need state management, routing or shadcn/ui components, not for simple single-file HTML or JSX.

The SKILL.md walks a five-step quick start: initialize the project, develop the artifact, bundle it to a single HTML file, share it, and optionally test or visualize it. Two shell scripts, init-artifact.sh and bundle-artifact.sh, do the mechanical work, and a tarball of shadcn components ships with them. The directory's read found no outside hosts and no environment variables.

I use it when the deliverable is an interactive prototype someone will open inside claude.ai: a calculator, a settings panel with real state, a multi-view dashboard mockup. For a production site it is the wrong tool, because the output is one bundled HTML file by design. It is Apache-2.0 licensed with about 115,000 installs recorded by skills.sh.

A prompt that uses its state and routing:

Build a claude.ai artifact: a three-tab pricing calculator with shared state, shadcn/ui components and a summary view. Bundle it to a single HTML file.

impeccable: auditing and polishing an interface

impeccable is the skill I would install first. It designs, redesigns, critiques, audits, polishes, simplifies, hardens and animates frontend interfaces: websites, landing pages, dashboards, product UI, forms, settings, onboarding, empty states, and native iOS or Android screens. It handles hierarchy, layout, typography, color, motion, UX copy, accessibility, responsive behavior and edge cases, and it can capture a design system as a DESIGN.md with tokens.

The SKILL.md is short (Setup, How to design, Modes, Commands) because the depth sits in reference files, one per job: adapt, animate, audit, bolder, clarify, colorize, component review and craft floor, plus native variants and an Android reference. It bundles five JavaScript scripts, and the directory's read flags network calls in them without naming an outside host.

Use it one playbook at a time: hierarchy, then typography, then accessibility and responsive layouts, then UX copy. Most polish problems are hierarchy problems wearing a color. It also handles the two notes every reviewer gives, making bland UI bolder and loud UI quieter. It is Apache-2.0 licensed, with about 379,000 installs recorded by skills.sh.

A prompt that starts the audit in the right place:

Audit the settings page in app/settings for hierarchy only. List the five worst problems in order, then fix the first two.

ui-animation: motion that earns its place

ui-animation builds, reviews and measures UI motion: springs, gestures, scroll effects, curve fitting from recordings, and sparse interface sound. It answers requests like "add animation", "match this easing", "reverse engineer this motion" and "add a click sound", and it can hunt for animation opportunities you missed.

Its SKILL.md is unusually complete for a motion skill: core rules, motion design principles, what to animate, easing defaults, transition decision rules, spatial and sequencing, accessibility, performance, anti-patterns, and separate discovery and reverse-engineer workflows. Reference files cover choreography, clip-path techniques, curve fitting and debugging symptoms. It bundles three Python scripts and ships evals, and the directory's read found no network calls.

Add it last. Motion layered on a weak hierarchy just moves the weakness around. The reverse-engineer workflow is the part I value most: give it a recording of an interaction you like and it fits the curve, so you match the feel instead of guessing at easing values. It is MIT licensed with about 11,000 installs recorded by skills.sh.

A prompt for the reverse-engineer workflow:

Here is a screen recording of a drawer opening in an app I like. Fit the easing curve and apply the same motion to our sidebar, with a reduced-motion fallback.

anydesign: turning a reference into a spec

anydesign analyzes images, websites and Figma files to extract their design, then writes a design.md with a token system, a component inventory and reconstruction notes. It responds to requests like "extract the design system from X" or "what palette does this site use", and its element mode handles single pieces, such as one navbar, with a focused element.md.

The SKILL.md enforces a five-step workflow: identify the source and objective, capture the material, run a layered analysis, generate design.md, then deliver. Seven Python scripts sit behind it, including capture_site.py, extract_colors.py, check_contrast.py and export_for_claude_design.py. The one outside host in its files is fonts.googleapis.com.

Start here when someone hands you a mood board and says "like this". A design.md with tokens is something an agent can build against; a screenshot is not. Be deliberate about the source: extracting tokens to learn from a site is analysis, shipping a copy of it is something else. It is MIT licensed with about 30 installs recorded by skills.sh, so read the SKILL.md before you trust it with client work.

A prompt with a clear objective:

Analyze these three screenshots of our old marketing site and generate a design.md with color and type tokens, a component inventory and contrast checks.

superdesign: comparing variants before you commit

superdesign designs or redesigns frontend UI, presentations and graphics on the Superdesign canvas with a choice of leading AI models. Its description covers pages, features, flows and brand-new products, reproducing existing UI, comparing results across models, exploring visual variants, setting or extracting a design system, and posters and marketing graphics. It can also generate supporting image or video assets when a design needs them.

The files are light. There are no bundled scripts; the skill runs its commands through npx, and its SKILL.md covers command examples, what to do when a command fails, and browser choice. The depth sits in references for websites, components, graphics, presentations and asset generation.

This is the AI UI design step I would not skip on a new product. Three directions side by side cost minutes; changing direction after the build costs the build. Use it to choose, then build the winner properly. It is MIT licensed with about 12,000 installs recorded by skills.sh.

A prompt that asks for a comparison, not one answer:

Design three directions for the pricing page on the canvas using different models. Keep the copy fixed, vary layout and type, then summarize the trade-offs.

How to use the stack together

  1. Start from a reference with anydesign. It turns images, websites or Figma files into a design.md with tokens and a component inventory. Now you have a spec instead of a mood board.
  2. Explore with superdesign. Compare directions across AI models before you commit, because changing direction later costs the whole build.
  3. Build with auteur. Fill in its commit-sheet, then let it produce the pages or product as one design system with generated assets.
  4. If the deliverable is a claude.ai artifact, swap step 3 for web-artifacts-builder. It builds with React, Tailwind CSS and shadcn/ui and bundles to one HTML file.
  5. Audit with impeccable, one playbook at a time: hierarchy, typography, accessibility and responsive layouts, then UX copy. Audit the built screens, not the mockups.
  6. Add motion last with ui-animation. It also reviews and measures motion, so use it to remove animation as often as to add it.
  7. Finish with impeccable again. A last accessibility and responsive pass catches what the motion and asset steps broke.

Common mistakes

  • Building before choosing a direction. superdesign makes the comparison cheap, so do it first.
  • Fixing color when the problem is hierarchy. Run the hierarchy playbook in impeccable before anything cosmetic.
  • Treating a screenshot as a spec. anydesign turns it into tokens and a component inventory an agent can build against.
  • Animating to hide a weak layout. The anti-patterns and transition rules in ui-animation exist to stop this.
  • Skipping reduced motion and contrast. ui-animation has an accessibility section and anydesign bundles a contrast checker.
  • Using web-artifacts-builder for a production site. It bundles one HTML file for claude.ai; treat it as a prototype tool.
  • Shipping without looking at the render. auteur builds a screenshot verification loop into every ship: check the pixels, not the diff.

Licenses, costs and checks before you install

Every license here is open. auteur, ui-animation, anydesign and superdesign are MIT; impeccable and web-artifacts-builder are Apache-2.0. None is proprietary.

None of the six reads an environment variable, according to the directory's read of their files, so there are no API keys to set. The network is another matter: auteur's files reach api.iconify.design, www.pinterest.com, www.awwwards.com and api.polyhaven.com, anydesign's reach fonts.googleapis.com, and impeccable's scripts make network calls without a named host. superdesign runs through npx on the Superdesign canvas, so check what that canvas asks of you.

The directory has not security scanned any listed skill; read how it handles trust. Read each SKILL.md before you enable it, and read the bundled scripts in the five skills that ship code.

FAQ

What is the best Claude Code design skill for UI work?

impeccable from pbakaus/impeccable (86/100) is the one I would install first for Claude Code design work. It covers hierarchy, typography, color, layout, accessibility, responsive behavior, motion and UX copy through focused playbooks, on the web and on native iOS or Android screens. Pair it with auteur (89/100) when you are building from nothing rather than fixing an interface that already exists.

Is impeccable alone enough?

For an interface that already exists, often yes: impeccable is a set of playbooks for fixing what is there, and at about 379,000 installs recorded by skills.sh it is the most installed skill in this stack by a wide margin. Run its playbooks in order. For a new product you still need something to build with, which is where auteur or web-artifacts-builder come in.

Can an AI UI generator build the whole interface from one prompt?

auteur comes closest. It designs and builds complete web experiences, including multi-screen products, as one design system, and it gates every ship with an anti-slop linter and a screenshot verification loop. superdesign generates and compares variants across AI models. Neither replaces review. Run an impeccable audit on whatever an AI UI generator produces, because a fast first draft is still a first draft.

Do these skills work in Codex and Cursor?

Yes. All six use the Agent Skills format, so the same folder works in Claude Code, Codex, Cursor and any other agent that reads a SKILL.md. The skills CLI installs for each of them, and every skill page in the directory shows the commands.

Does this stack cover mobile?

Partly. impeccable's playbooks cover frontend and native interface design, according to its summary, and anydesign will extract a token system from any screenshot you give it. auteur, superdesign and web-artifacts-builder are web-first. If the product is a native app, start with those two and pick a framework-specific skill from the directory for the build.

Are these AI UI design skills free?

The skills are open source: four are MIT licensed and two are Apache-2.0, and none reads an API key from the environment, per the directory's read of their files. The services around them are another matter. superdesign works on the Superdesign canvas with a choice of AI models, and auteur reaches outside hosts such as api.iconify.design and api.polyhaven.com. Check those terms before you depend on them.
