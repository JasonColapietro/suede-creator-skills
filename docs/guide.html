A run, start to finish.

You do not call skills by name. You describe the outcome, the agent matches your request against the one-line descriptions, and it loads the body of the skill it picks. Here is that loop with suede-visibility-grader, using the real lanes defined in its SKILL.md.

claude code · what you type 
> grade my landing page before I launch it
> https://example.com/pricing
1 · RouteNo skill name required. The description “grade a public page for launch appeal” matches, so the agent loads that one folder. Every other skill stays on disk.
2 · InspectThe skill forbids grading from memory. It pulls the live URL, status code, canonical, robots, sitemap, rendered first viewport, headings, CTAs, Open Graph, and JSON-LD before scoring anything.
3 · ScoreFive lanes, each graded A–F from inspection evidence and mechanical caps, never impression or generosity, then one overall grade.
4 · Hand backA grade per lane, the evidence behind each, and the ranked fixes. The verdict is advice: a failed gate changes what the agent reports, never what it does.

What comes back

The five lanes the grader scores, and the question each one answers.

A–FFindabilityStatus, canonical, robots, sitemap, title, description, durable keywords, duplicate URL risk.
A–FFirst-screen clarityDoes the rendered first viewport answer who this is for, what changes for them, and what to do now, without scrolling?
A–FCTA pullPrimary action, secondary proof action, button text, link targets, and whether there is a reason to click now.
A–FProof and trustScreenshots, commands, docs, live routes, source files, receipts, authorship, and evidence boundaries.
A–FAI readabilityCan a model summarize and cite the page without hallucinating? Structured lede, citation-ready headings, sourceable claims, entity schema, internal links.
Read the full skill

Same loop for every other lane: describe the outcome, let routing pick, read the evidence it hands back. Fixes that are conversion-shaped route onward to site alchemy; a page shipping as part of a release routes to launch packaging.

Installing every skill does not cost you every skill.

The objection to a big pack is always context. It does not apply here: the agent reads a one-line description per skill and loads the body of exactly the one it picks. Everything else stays on disk.

Before launchRun design QA, copy cleanup, visibility and CTA grading, SEO/AEO/AI EO metadata, schema checks, link sweeps, and evidence review.

Install for Codex and Claude.

These are standard SKILL.md folders with bundled references, templates, and Python scripts. Review the contents before enabling code execution.

Claude Code: first install

First install takes two commands: add the marketplace, then install the full pack. After the marketplace is present, install or update is one command. Use MCP only when structured discovery, audit scaffolds, install options, or QA checklists would help.

/plugin marketplace add JasonColapietro/suede-creator-skills
/plugin install suede-skills@suede
Install and MCP docs Public explainer

Codex: full pack

Add the Codex-native marketplace, then install every skill and three read-only MCP profiles. Use the direct skill installer only when you want one selected skill.

codex plugin marketplace add JasonColapietro/suede-creator-skills --ref main
codex plugin add suede-skills@suede-codex

Claude Code: manual

Install into a project .claude/skills folder or your user-level ~/.claude/skills folder.

git clone https://github.com/JasonColapietro/suede-creator-skills.git /tmp/suede-creator-skills
cd /path/to/your-project
mkdir -p .claude/skills
cp -R /tmp/suede-creator-skills/skills/suede-workflow-skills .claude/skills/

Suede workflow FAQ.

Short answers for builders, designers, agencies, creators, developers, and agents deciding whether the public Suede skill pack fits their workflow.

What are Suede Creator Skills?

Suede Creator Skills are free, open-source SKILL.md folders for Claude Code and OpenAI Codex. Original work is MIT licensed, and adapted components retain their upstream notices. The pack covers multi-agent orchestration, code review with an A-F ship grade, CI ship-gates, AI evals, Suedify website restyling, design QA, conversion copy, SEO/AEO/AI EO audits, visibility grading, launch packaging, and a creator toolkit for campaigns, release prep, and rights evidence.

Which workflows do the skills support?

The skills support reference-site restyling, website redesign, copywriting, GitHub Pages polish, visibility and CTA grading, SEO/AEO/AI EO metadata, schema checks, public docs, launch packaging, code review with A-F grading, CI ship-gates, AI evals, and QA, plus artist campaign packaging and creator rights utilities.

When should I use Agent Teams?

Use Agent Teams when work is large, risky, public, cross-surface, release-bound, design-heavy, or likely to collide with user or other-agent WIP. It scouts first, splits safe lanes, keeps shared context fresh, reviews the result, verifies release truth, and records evidence.

Do the skills copy websites exactly?

No. Suedify studies layout, rhythm, typography, color roles, motion, and proof structure, then recreates the design grammar with target-owned content and assets.
